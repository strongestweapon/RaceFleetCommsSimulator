경기정 통신 시뮬레이터 v0.9.6

실행
  macOS 앱: RaceFleetCommsSimulator.app을 엽니다. 앱에 화면과 계산 파일이 포함됩니다.
  macOS에서 빌드: Rust·Xcode·Tauri CLI 2가 있는 환경에서 cargo tauri build --bundles app -- --locked
  기본 빌드 위치: src-tauri/target/release/bundle/macos/RaceFleetCommsSimulator.app
  앱의 탐색 탭에서 기록 저장과 조건 불러오기를 누르면 macOS 파일 창이 열립니다.

브라우저에서 실행
  이 폴더에서 npm start
  http://127.0.0.1:8876 접속
  Node.js 20 이상. 외부 패키지 설치나 인터넷 연결은 필요하지 않습니다.
  다른 포트: RADIO_LAB_PORT=8877 npm start

검증
  npm test

조작
  지도 상단에 회차와 통과 여부가 표시됩니다. 지도 재생 위치를 바꿔도 해당 회차의 전체 평가 결과는 유지됩니다.
  예정, 실제 송신, 수집기 수신을 구분합니다. 실제 송신 시작은 보고당 한 번만 셉니다. 배를 선택하면 해당 배의 세 건수를 확인할 수 있습니다.
  실제 송신 후 기한 내 수신이 0건인 경기정은 빨간 윤곽으로 표시합니다. 송신이 없었던 경기정은 회색입니다.
  결과 탭에서 지도와 평가 결과, 최근 200회 탐색 그래프를 함께 봅니다.
  그래프를 누르면 해당 회차가 지도에 표시됩니다. 이력 탭의 스냅샷에서 저장된 통과 조건을 선택해 다시 볼 수 있습니다.
  스타트 라인 왼쪽은 핀마크, 오른쪽은 수신 전용 RC 보트입니다. ILCA 스타트 라인 길이는 척수 × 6.36m입니다.
  화살표는 경기정에서 수집기로 들어가는 방향입니다. BLE Mesh는 중계 경기정을 경유할 수 있습니다.
  기본값: ILCA 첫 업윈드, 100척, 대형 폭 기준 70m, 각 배 1Hz, 24바이트.
  지도 왼쪽 위 또는 코스 탭에서 스타트 밀집·첫 업윈드·풍상 마크 회항·풍하 레그·풍하 게이트 회항을 선택합니다.
  풍하 게이트는 영국 내셔널 ILCA 7 R14의 G3처럼 두 부표로 표시합니다. 경기정은 사이로 들어와 3S(왼쪽, 청록색)나 3P(오른쪽, 노란색)의 바깥으로 돌아 다시 풍상 쪽으로 향합니다.
  M1은 스타트 라인에서 풍상 1,100m가 기본입니다. G3는 ILCA 운영 지침 §6.5–6.6을 적용해 폭 42.4m, 중심은 풍상 93m가 기본입니다. 풍하 게이트 위치에서 라인 위·아래를 설정할 수 있습니다.
  코스 재생은 M1 회항부터 G3까지 보여줍니다. 풍하 게이트 회항 배치에서 누르면 접근과 두 갈래 회항을 확대해서 재생합니다. 슬라이더로 시점을 이동합니다.
  코스 재생은 통신 평가와 별도입니다. 평가 속도가 0kn이면 코스 재생에만 5kn을 사용합니다.
  조건 옆 체크박스를 켜면 해당 값만 자동 탐색합니다.
  기본 척수와 배 간격은 고정되어 있습니다. 체크하면 함께 탐색합니다.
  화면 간격은 기본 1초, 최소 0.1초입니다. 각 후보의 수신 판정은 0–1초 구간에서 합니다.
  계산이 요청 간격보다 길면 끝난 뒤 다음 평가를 시작하며, 평가를 겹쳐 실행하지 않습니다.
  실제 계산 시간과 평가 시작 간격을 화면에 표시합니다.
  고속 탐색을 누르면 지도와 그래프를 접고 다음 후보를 기다림 없이 계산합니다. 평가 대상과 체크한 범위는 탐색 탭 설정을 따릅니다.
  무선별로 같은 입력의 결과를 재사용하고, 경기정 배치와 전파 조건이 같으면 링크 계산을 공유합니다.
  고속 화면은 평가 횟수, 성공 횟수, 새 스냅샷 수를 표시합니다. 이력 탭의 스냅샷에서 고속 탐색으로 찾은 통과 후보 중 새 최선을 다시 볼 수 있습니다.
  고속 탐색이 끝나면 미송신·1초 초과·충돌·신호 부족 집계와 실패 회차별 요약이 열립니다. 두 방식을 평가했다면 분석에서 방식을 바꿔 볼 수 있습니다.
  이번 실행의 실패 분석은 이력 탭에서도 열 수 있습니다. 실패 집계와 회차 요약은 앱을 닫거나 고속 탐색을 새로 시작하면 지워집니다.
  기본 탐색은 체크한 항목을 지정한 범위에서 무작위로 뽑습니다.
  카드 밑의 최소·최대 값을 누르면 해당 항목의 자동 탐색 범위를 편집합니다.
  배치, 차폐 방향, 접근 방식처럼 이름이 있는 값은 후보를 선택합니다. 최소와 최대가 같으면 값이 고정됩니다.
  범위는 브라우저 설정과 기록 저장 파일에 보관됩니다.
  순차 비교와 주변 조합 탐색도 같은 범위를 따릅니다.
  나빠진 후보는 이력에 남기고 보관한 해를 유지합니다. 22% 확률로 다른 구간도 시험합니다.
  순차 전용은 한 바퀴 후 자동 정지합니다. 모든 조합을 완전 탐색하는 것은 아닙니다.
  통신 성능을 비교할 때는 척수·간격·속도·파도를 자동 탐색에서 빼고 고정하세요.
  환경까지 체크하면 환경과 통신 설정을 함께 바꿔 통과 조건을 찾습니다.
  코스 탭의 송신 요청 시점에서 기본 분산, 4그룹 동시, 전부 동시를 비교합니다. LoRa TDMA는 배정 슬롯을 기다리고, 기한에는 그 대기 시간도 포함됩니다.
  파도 세기는 유의파고 Hm0(m), 대표 주기는 초로 입력합니다.
  이동 속도 기준(kn)은 배별 70–130%로 분산하며 같은 시드에서 재현됩니다.
  장면 재생/시간 슬라이더로 구간 안의 배 이동과 기울기를 확인합니다. 성과 수치는 구간 합계입니다.
  탐색 정지를 누르면 화면에 남은 평가의 조건과 수신 결과를 확인할 수 있습니다.
  발견한 최선 카드를 누르면 해당 경기장과 조건을 확인할 수 있습니다.
  새 최선이 나올 때 해당 조건과 시드를 앱 로컬 저장소에 스냅샷으로 보관합니다. 스냅샷을 다시 열면 그 설정으로 재계산합니다.
  이력 그래프를 누르면 해당 조건을 같은 시드로 재계산합니다.
  배를 클릭하거나 배 선택을 바꾸면 수신율과 마지막 완료 경로를 확인합니다.
  다른 시드 5회 검증은 배치 미세 위치, 중계선 선정, 페이딩, 송신 위상을 바꿔 재평가합니다.
  기록 저장: 현재·최선 조건과 최대 최근 2,000회 이력을 JSON으로 저장합니다.
  조건 불러오기: 저장 파일의 현재 조건으로 새 탐색을 시작합니다. 이전 탐색 상태를 재개하지는 않습니다.
  입력값이나 탐색 변수를 바꾸면 이전 극값과 섞이지 않도록 새 탐색으로 시작합니다.

범위
  BLE: 레거시 1M 광고 기반 관리형 플러딩의 패킷 이벤트 근사.
  LoRa: TDMA 또는 임의 위상 주기 송신으로 수집기에 직접 전달. LoRa 중계는 미구현.
  수집기마다 LoRa 채널 수만큼 수신기가 있고, 수집기 백홀은 충분하다고 가정합니다.
  속도 0이면 정지, 그 외에는 배별 초기 침로 또는 주어진 가상 경로를 따릅니다. 바람으로 항로를 계산하거나 배 사이 충돌을 회피하는 모델은 포함하지 않습니다.
  파도는 예시 3성분 파형입니다. 0.1초마다 수직 안테나 높이·편파 손실·파도 페이딩을 갱신합니다.
  긴 패킷 수신 도중에도 상태를 재검사합니다. 파도 효과의 수치는 실측 보정 전 가정입니다.
  파고를 키워도 모든 개별 표본에서 수신율이 나빠지는 단조 관계를 강제하지 않습니다.
  Vakaros의 독자 메쉬를 재현한 모델이 아닙니다.
  등록·페어링·재부팅·GNSS/PPS 상실·기기 전력 소모는 미구현입니다.
  자세한 근사, 감도 보간, 충돌 판정, 미구현 사항과 자료 링크는 화면 아래에서 확인합니다.

해석
  새 평가에서는 시작부터 1초까지 모든 경기정이 실제 송신하고, 수집기가 각 경기정의 패킷을 한 건 이상 받아야 통과합니다.
  지도 상단의 수신 척수는 현재 시험 결과입니다. 성공 횟수는 현재 탐색에서 전원 수신에 성공한 누적 횟수입니다.
  두 방식을 평가 대상으로 선택하면 둘 다 통과해야 합니다.
  이력 탭의 LoRa 100척 검증 스냅샷은 별도 시드의 파고·배치·지터 검증 요약을 포함합니다.
  통과 조건끼리 최장 갱신 공백, 예정 기준 패킷 도착률, P95 지연을 비교합니다. 그래프의 세로축은 패킷 도착률입니다.
  경기정은 수면 위 0.8m ±0.2m에서 배별 장착 높이를 배정합니다. 같은 시드를 사용하면 두 통신 방식의 높이가 같습니다.
  전파 탭에서 기준 높이와 편차를 수정합니다. 편차 0m는 모든 경기정에 같은 기준 높이를 적용합니다.
  전파 탭에서 차폐 중심 방향과 최대 손실을 바꿉니다. 기본 선미 4dB는 비교용 가정입니다.
  지도에서 배를 선택하면 RC 상대방위, 방향 손실, 직접 링크 RSSI를 확인할 수 있습니다.
  체크된 범위에서 관측한 통과 조건 중 최선입니다.
  단위 테스트는 계산과 소프트웨어의 일관성을 확인합니다. 해상 예측 정확도를 검증한 것은 아닙니다.
  실측 수신 전력·패킷 손실·안테나 높이·차폐·간섭 시험으로 모델을 보정한 뒤 설계 결정에 사용하세요.
